# 设计与代码深度审查

审查基线：7aecc78。审查日期：2026-11-02。范围包含系统设计、Kafka专项设计、接口、模块边界及现有21个测试。基线审查结论：可靠性方向合理，但当时实现只是骨架，不能以依赖已引入和启动成功代替服务已完成。高流量规模是假设，不能当成经过验证的部署建议。

## 发现与修订决策

| 优先级 | 发现与后果 | 修订决策与验收 |

## 实施约束

采用模块化服务，不为了展示技术搭建新的账户、广告、CRM或库存系统。运行基线必须能在小型测试环境完成同样的一致性协议；64分片、三AZ丢失和10万QPS属于更高规模的验收，不用单机测试冒充完成。

MyBatis保留显式SQL和同库事务，域层仍无Spring依赖。生产配置不得默认允许localhost/任意URL；测试对本地供应商mock的豁免只能显式开启。业务请求体、供应商凭证和响应正文不能进入日志。

## 复核方式

每个问题应对应到实际实现与测试报告；以最终README与验证记录为当前执行事实。本文保留原始审查发现，不在实现后改写成“从来没有问题”。安全检查、可靠性不变量、失败日志与修复提交是面试时应展示的证据，而不是测试数量或配置项数量。

## 修订后的结论

运行链路已经实现，原来的501仅保留在scaffold模式。真实PG/Kafka测试促成了UUID绑定、bytea映射和Kafka元数据传播三个实际修复；审查还补齐了非法Handoff组合、目标版本登记、幂等Header碰撞、原始Outbox到期时间、容量背压、保留期、分片身份和有界I/O。架构图明确了Worker进程边界、外部平台和恢复路径，并提供了单独的时序与部署视图。

代码已完成机械格式化，便于逐类审查。最新执行结果及未完成的生产验收见验证记录。仍需要谨慎的判断是：高流量规模没有被小型CI证明；外部配额协议必须落实；当前是固定拓扑和启动加载配置，不是自动在线迁移或热配置平台；在线DEK轮换与供应商特殊业务码需要额外协议和实现。
